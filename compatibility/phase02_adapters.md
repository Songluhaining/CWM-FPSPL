# 阶段02兼容与协议差异

以下均为明确命名的适配，不改动原版源码，也不把结果称为论文原协议复现。

## 分类器

- 六维基线：读取CLAP的 `classify_by_svm`，验证其前两句仍为 `SVC(kernel='linear')` 与训练调用后，只执行这两句。原函数同时要求测试真值并写指标，故将后半段移至本项目独立评价进程。训练构造参数保留原样。
- PULP：直接调用快照中的 `PUBaggingLearning._train_pu_bagging`。以原始失败观测选择正例，以训练中的原始通过产品作为无标签集合；不调用会接收FP/TP真值的 `prepare_data`。保留30个线性支持向量基分类器、5%无标签有放回抽样、类别平衡、训练内概率估计、代理负例训练准确率加权。训练完成后用冻结基分类器预测留出产品，不再把留出产品加入训练池。
- 该PULP实现与论文“代理负例数等于失败产品数、逐样本仅聚合未抽中轮次”的规则不同；本阶段没有默默替换原实现。单元测试核对冻结评分在原训练通过集合上与原 `_ensemble_predict` 的分类结果一致。
- 额外监督基线为五十维逻辑回归和线性支持向量分类；测试规模／覆盖率两维逻辑回归作捷径对照。三者的正则化参数只按验证集合选择。六维原分类器与原PULP参数固定。

## 特征

原PULP `calculate_attributes3` 遍历 `ranking_suspicious_stmts` 的返回值，期望每项是分数字典；当前排名函数实际只返回单个Ochiai字典，迭代后得到字符串。将其交给 `normalized_dict` 会产生 `AttributeError: 'str' object has no attribute 'keys'`。本项目用明确标为合成输入的回归测试复现此类型冲突，不在原数据树调用有写入／删除行为的完整特征函数。

本地旧试跑脚本曾补齐十公式返回结构。当前实现按相同顺序读取原始频谱公式：Jaccard、Op2、Tarantula、Barinel、Ochiai、Russell–Rao、Dstar、GP02、GP03、GP19。保留原公式中GP19和切片权重分母的现有行为：后者用字典中字典序最大的语句键对应的分数，而非数值最大分数。没有宣称这是论文公式修正后的结果。

严格适配与原特征生成的差异：

1. 所有可疑度统计、语句词典、分数归一化及失败路径／静态切片参考池仅来自本折训练产品；参考池按系统名称隔离。原代码使用当前缺陷版本的产品池。这里的变化使得实验问题更严格，也使两种协议的分数不能直接比较。
   本实现的词典是所有训练产品的可用语句并集；原代码的排名搜索范围来自失败产品。频谱计数重新取自每个测试的二值命中，不能把旧属性表当作该实现的输入。训练正例池按原始失败观测选取，包含来源表中曾被转换为假通过的产品，与原来源标签表筛选出的失败池也不同。
2. 计算训练失败产品的路径／切片相似度时排除自身参考；可疑度统计仍来自完整训练集合。模型输入只含最终固定的6／50／2个数值，不编码系统或版本名称。
3. 留出系统没有同系统训练词典，不能将碰巧同名的语句当作跨系统语义对应；相应五十维先验特征为0并记录无证据计数。六维保留产品自身的测试可诊断性统计，两维保留自身覆盖率与测试规模。这是适配的信息限制，不是论文方法原协议的性能结论。
4. 覆盖率解析仅提取位置映射和计数；忽略 `buggy` 等真值属性。分支命中采用语句计数、真分支计数、假分支计数中任一为正，避免旧代码的分支遗漏。映射缺失或冲突直接报错。
5. 显式处理零分母为0并计数，不生成虚构状态或干预观测。静态切片只做集合相似度，不声称因果图或动态定义使用关系。
6. 外部切片副本的组合Java源码与原产品逐文件散列一致才可使用；这能验证副本身份，不能证明切片算法的语义正确性。

## 原协议保留状态

CLAP原文的按版本交叉验证和留一系统实验、PULP原文的版本内／汇总正例与无标签协议在报告中分别记录。本地缺正式823成员清单、四系统、多缺陷版本及隔离后的模拟套件，本阶段不给这些原协议填入虚构分数。当前结果的协议名固定为 `strict_train_reference_v1`。

## 访问边界

数据准备不读标签；训练仅允许本折 `train.csv`；参数选择进程只调用验证标签；冻结模型预测过程无标签；最终评价进程才连接各分区目标和来源，写入 `outputs/metrics/`。模型进程的Python文件访问检查拒绝该指标目录、其他分区标签、变异日志和旧属性表。

这是程序角色隔离，不能替代独立操作系统账户或容器权限。没有创建不同Windows账户，也没有宣称所有外部程序都无法绕过接口。模拟套件持续禁用，因此原始F的失败测试不冒充“隐藏后重新发现”的新失败。
